# 提出前チェックリスト

提出の前と、コンテストの終了前に確かめる項目だ。

## 出力

- [ ] 出力の形式が問題文と合っている
- [ ] 最良の解を出力している。最後の状態ではない
- [ ] 制約に違反する解を出力する可能性がない
- [ ] デバッグ用の出力が標準出力に混ざっていない

## 時間とメモリ

- [ ] 手元の最大の実行時間が制限時間より十分に短い
- [ ] 入力が最大のケースでも、時間内に終わる
- [ ] 提出したバージョンの実行時間を、提出結果の画面で確かめた
- [ ] メモリの使用量が制限に収まっている

ジャッジの計算機は手元より遅いことがある。制限時間の95%を超えるケースがあるなら、終了時刻を早める。

## 正しさ

- [ ] 手元の数百ケースで、失敗したケースがない
- [ ] 差分で求めたスコアと、最初から計算したスコアが一致する
- [ ] 手元のスコアと、提出結果のスコアが大きく食い違っていない
- [ ] デバッグ用の検算や、遅くなるオプションを外した

## パラメータ

- [ ] 調整で見つけた値を、既定値として書き込んだ
- [ ] 環境変数がない状態で実行して、意図した値が使われることを確かめた
- [ ] 乱数のシードが固定されている

## human only部門

- [ ] スニペットを貼った部分に、公開先のURLのコメントが残っている
- [ ] コンテスト中に、生成AIへの質問や、ルールにない補完機能を使っていない
- [ ] 最新のルールを読んだ

## 終了前

- [ ] 最後に提出したバージョンが、出したいバージョンである
- [ ] 最終のテストで評価される提出がどれかを、コンテストのルールで確かめた

AHCでは、最後の提出が最終のテストに使われる形式が多くある。終了の間際に試しの提出をすると、そのバージョンが最終の結果になる。

## 提出のあと

コンテストが終わったら、上位の解法と解説を読む。自分の解法と違う点を書き出し、次のコンテストの前に見直す。
