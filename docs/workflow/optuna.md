# パラメータ調整

温度、近傍を選ぶ確率、評価関数の重みなどのパラメータは、最後に自動で調整する。手で調整するより、短い時間でよい値が見つかる。

## 調整する時期

パラメータの調整は、解法の形が固まってから行う。近傍や評価関数を変えると、最適なパラメータも変わるからだ。

短期コンテストでは最後の30分から1時間、長期コンテストでは最後の1〜2日が目安だ。解法を改善する案が残っているうちは、そちらを先に進める。

## Optunaでの調整

[Optuna](https://optuna.org/)はパラメータを自動で探すPythonのライブラリだ。次の流れで使う。

1. パラメータごとに、探す範囲を決める。
2. Optunaが提案した値を環境変数に入れて、多数のケースを実行する。
3. 相対スコアの平均などの指標を、Optunaに返す。
4. これを数十回から数百回繰り返す。

温度のように、何倍になるかが重要なパラメータは、対数の目盛りで探す。

pahcerには、Optunaと組み合わせるサンプルが付いている。

## 見込みのない試行の打ち切り

1回の試行で全ケースを実行すると、時間がかかる。OptunaのWilcoxonPrunerを使うと、それまでの最良の試行より明らかに悪い試行を、途中で打ち切れる。PFNの記事の実験では、評価の回数が半分以下になっている。

使うときは、ケースの実行順を試行ごとにシャッフルし、スコアと一緒にケースの番号を渡す。

## 手で決めた値の利用

手で調整した値があるなら、それを最初の試行として与える。そこから探索が始まるので、手で調整した値より悪い結果で終わることがなくなる。

## 検証

調整に使ったケースとは別のケースで、スコアを確かめる。調整に使ったケースにだけ合った値になっていることがあるからだ。

調整の前後で、検証用のケースのスコアが上がっていれば採用する。

## 入力に応じたパラメータ

最適な値が入力の大きさなどで変わる問題では、入力の条件ごとに調整する。条件の範囲をいくつかに分けて、範囲ごとに値を持つ方法が簡単だ。

## 計算資源

調整には多くの実行が必要だ。手元の計算機で足りなければ、クラウドの計算機を短い時間だけ借りる方法がある。terry_u16さんは、176個の仮想CPUを使った調整が約200円だったと書いている。

## よくある失敗

実行時間をパラメータにすると、長いほどよいという結果にしかならない。時間は固定する。

並列の数が多すぎて1ケースの実行が遅くなると、本番と違う条件で調整することになる。
