# chokudaiサーチ

chokudaiサーチは幅のごく狭いビームサーチを、制限時間まで何度も繰り返す手法だ。見つけた状態は捨てずに、深さごとの優先度つきキューに入れておく。

## 使う場面

ビーム幅の調整に時間をかけられないときに使う。制限時間までループを回すだけで、時間を使い切れる。

評価関数に現れない要素が重要な問題でも、ビームサーチよりよい結果になることがある。同じ計算量で、より多くの種類の展開を調べるためだ。

## 考え方

1. 深さごとに優先度つきキューを用意し、深さ0のキューに初期状態を入れる。
2. 深さ0から順に、各キューから最もよい状態を取り出し、次の候補をすべて次の深さのキューに入れる。
3. 最後の深さまで進んだら、深さ0に戻って同じことを繰り返す。
4. 制限時間が来たら、最後の深さのキューにある最もよい状態を答えにする。

1回目は幅1のビームサーチ、つまり貪欲法と同じだ。2回目からは各深さで、まだ展開していない状態のうち最もよいものが展開される。

## 実装例

[chokudaiサーチの骨格](/snippets/#chokudai-search)は、ビームサーチの骨格と同じ形の状態を受け取る。

```cpp
auto actions = chokudai_search(init_state, max_turn, 1, timer, TIME_LIMIT);
```

3つ目の引数は1回の繰り返しで各深さから取り出す状態の数だ。

## ビームサーチとの違い

| 項目 | ビームサーチ | chokudaiサーチ |
|---|---|---|
| 時間の管理 | 幅の調整が必要 | 制限時間まで回すだけ |
| 多様性 | 工夫が必要 | 自然に保たれる |
| メモリ | 直前の世代だけ | 見つけた状態をすべて持つ |
| よい状態の展開 | 上位に集中する | 早い時点の探索が無駄になりやすい |

考案者のchokudaiさんは、評価関数を改善していけば、ビームサーチとの差は小さくなるとしている。

## よくある失敗

見つけた状態をすべて持つので、状態が大きい問題ではメモリが足りなくなる。キューの大きさに上限を設けるか、評価の悪い状態を定期的に捨てる。

スニペットの実装は重複除去をしていない。同じ状態が多く作られる問題では、ハッシュ値で重複を除く処理を足す。
