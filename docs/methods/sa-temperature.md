# 焼きなましの温度と受理判定

温度は悪くなる変更をどれだけ受け入れるかを決める値だ。開始温度、終了温度、下げ方の3つを決める。

## 温度の目安

温度は1回の変更で起きるスコアの変化と同じ単位の値だ。悪化の量がdのとき、受理確率は e^(−d/T) だ。dがTと同じなら約37%、Tの3倍なら約5%になる。

開始温度はよくある悪化の量と同じくらいから試す。終了温度は最も小さい悪化もほとんど受理されない値にする。

決め方に迷ったら、いくつかの解でランダムに近傍を試し、差分の絶対値の分布を出力する。その分布の大きい側を開始温度、小さい側を終了温度の目安にする。

## 下げ方

よく使われる下げ方は2つある。tは経過時間の割合で、0から1まで動く。

- 指数: T = T0 × (T1 / T0)^t
- 線形: T = T0 + (T1 − T0) × t

どちらがよいかは問題によって違う。[焼きなましの骨格](/snippets/#sa)は指数を使っている。式を1行変えれば線形になるので、両方を試して比べる。

温度は反復回数ではなく経過時間で決める。実行環境の速さが変わっても、制限時間の中で温度が最後まで下がる。

## 受理判定

受理の条件は0以上1未満の乱数rを使って e^(Δ/T) > r と書ける。両辺の対数をとると、次の形になる。

```
Δ > T × log(r)
```

右辺は差分を計算する前に決まる。これをしきい値として先に求めておくと、expを呼ぶ必要がなくなる。差分の計算の途中で、しきい値を下回ることが確定したら、そこで計算を打ち切れる。

log(r) の計算も[logの表](/snippets/#log-table)で置き換えられる。

## 調整の手順

1. 上の目安で開始温度と終了温度を決める。
2. 開始温度を数倍、数分の1に変えたバージョンを、同じケースで比べる。
3. 終了温度も同じように比べる。
4. 余裕があれば、Optunaで自動調整する。

Psyhoさんは、温度は3〜4回の実行で決まることが多いとしている。温度より、近傍と高速化に先に時間を使う。

## よくある失敗

スコアの規模が入力によって大きく変わる問題では、固定の温度が合わないケースが出る。入力から求めた値で温度を決めるか、スコアを正規化する。

温度の設定を誤ってほぼ0になっていた、という失敗の報告もある。受理率を出力していれば気づける。
