# 差分更新型ビームサーチ

差分更新型ビームサーチは状態を候補ごとにコピーしない実装です。1つの状態を、行動の適用と巻き戻しで動かして、各候補の状態を再現します。

## 使う場面

状態が大きく、1手で変わる部分が小さい問題で使います。大きな盤面の一部だけを動かす問題が代表です。状態のコピーに時間の大半を使っているなら、この実装で大きく速くなります。

遷移の計算がコピーと同じくらい重い問題では、素直な実装で足ります。

## 考え方

ビームに残っている状態は、初期状態からの行動の列で表せます。行動の列を木にまとめると、根が初期状態、葉がビームの各状態になります。

この木を深さ優先の順にたどります。子へ進むときに行動を適用し、親へ戻るときに巻き戻します。葉に着いたとき、手元の状態はその葉の状態になっています。そこで次の候補を列挙します。

状態に必要な関数は3つです。

- 行動を適用する
- 行動を巻き戻す
- 次の候補を評価値とハッシュ値つきで列挙する

候補は軽い構造体で持ち、残すと決まったものだけを木に追加します。次の世代で子が1つも残らなかった葉は、木から削除します。

## 高速化の工夫

木の根の近くは、子が1つだけの一本道になりやすい部分です。一本道は一度だけ進み、根をその先へ移します。毎回の往復が減ります。

木の表し方には、次のものがあります。

- 各ノードに親、兄弟、最初の子の添字を持たせる
- 木の辺を深さ優先の順に並べた配列で持つ

eijirouさんの計測では、後者のほうが速く動いています。

候補を選ぶ部分ではビーム幅の数だけ集まったあと、残っている最悪の候補より悪い候補をすぐに捨てます。

## 巻き戻しの注意

巻き戻しには、適用の前の値が必要です。適用するときに元の値を行動の中へ保存しておくと、巻き戻しで使えます。

浮動小数点数の値は、逆の計算で戻しても元の値と一致しないことがあります。状態には持たせず、候補や行動の側に持たせます。

## よくある失敗

適用と巻き戻しが正しく対になっていないと、状態が少しずつずれていきます。デバッグ用に、葉に着いたときの状態を、行動の列を最初から適用した状態と比べる処理を入れます。
