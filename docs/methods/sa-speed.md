# 焼きなましの差分計算

焼きなまし法は、試行回数が多いほどよい解に届きます。1回の試行にかかる時間を減らすことが、スコアに直接つながります。

## 高速化の前に確かめること

制限時間を10倍に延ばして実行し、スコアがどれだけ上がるかを見ます。大きく上がるなら、高速化に取り組む価値があります。ほとんど上がらないなら、近傍や評価関数を先に見直します。

どこに時間がかかっているかは、プロファイラで計測します。予想と違う場所が遅いことがよくあります。

## 差分計算

変更によって変わる部分だけを計算します。巡回路の2-optなら、変わる辺は2本だけなので、差分は4つの距離から求まります。

差分計算を速くするために、補助のデータを持ちます。たとえば次のようなものです。

- 行ごと、列ごと、グループごとの合計
- 各要素がいまどこにあるかを表す逆引きの配列
- マスごとの寄与をあらかじめ計算した表

補助のデータの更新は、変更が受理されたときにだけ行います。焼きなまし法では受理されない試行のほうが多いので、判定を軽くし、受理されたときの更新が少し重くなる形が有利です。

## 状態を変える前の判定

状態を書き換えてから差分を計算し、受理されなければ元に戻す、という書き方は実装が簡単です。ただし受理されない試行のたびに、書き換えと復元が起きます。

差分だけを先に計算し、受理されたときにだけ状態を書き換える形にすると、この無駄がなくなります。[焼きなましの骨格](/snippets/#sa)はこの形です。

最初は簡単な書き方で動かし、正しく動くことを確かめてから書き直します。

## ループの中の細かい処理

1回の試行が軽い問題では、次の処理がボトルネックになります。

- 時刻の取得。数百回に1回だけ行います
- 乱数の生成。xorshiftなどの軽い生成器を使います
- expとlog。受理のしきい値を先に決める形にすると、expは要りません
- 剰余の演算。乱数の範囲の変換は掛け算とシフトでできます
- メモリの確保。ループの中で配列を作らず、外で確保して使い回します

## 検算

差分計算は間違えやすい部分です。デバッグ用に、受理のたびにスコアを最初から計算し、差分で求めた値と比べる処理を入れます。提出するときは外します。
