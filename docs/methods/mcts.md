# MCTS

MCTS（モンテカルロ木探索）はプレイアウトの結果を木に蓄え、有望な手順ほど深く調べる手法です。

## 使う場面

対戦ゲームのように、相手の応手も考える必要がある問題で使います。一人で解く問題でも、終盤の数手を詰める場面で使われた例があります。

AHCでは、焼きなまし法やビームサーチほど出番は多くありません。評価関数を作りにくく、プレイアウトが速い問題で候補になります。

## 考え方

各ノードに、試行回数nと、結果の合計wを持たせます。次の4つの処理を繰り返します。

1. 選択。根から、評価の高い子を選びながら葉まで降ります。
2. 展開。葉の試行回数がしきい値に達していたら、次の手を子として追加します。
3. プレイアウト。葉の状態から最後までシミュレーションします。
4. 伝播。結果を葉から根までのすべてのノードに加えます。

選択で使う評価には、UCB1がよく使われます。

```
w / n + C × sqrt(2 × ln(t) / n)
```

tは兄弟のノードの試行回数の合計、Cは定数です。1つ目の項はこれまでの成績です。2つ目の項は、試行回数が少ない子ほど大きくなります。成績のよい子を深く調べながら、あまり試していない子にも機会を与えます。

制限時間が来たら、根の子のうち試行回数が最も多いものを選びます。

## 原始モンテカルロ法との違い

原始モンテカルロ法は最初の1手だけを比べ、2手目より先はすべてプレイアウトに任せます。MCTSは、有望な手順については2手目より先も木に含めます。試行を重ねるほど、先の手まで考えた評価になります。

## 設計で決めること

- 展開のしきい値。小さいと木が早く深くなり、大きいと評価が安定してから展開します
- 定数C。スコアの規模に合わせます。スコアを0から1の範囲に直すと決めやすくなります
- 子の数。候補が多いときは、軽い基準で有望な数個に絞ります
- プレイアウトの方法。ランダムより、貪欲法を混ぜたほうがよいことが多いです

## 入力がランダムな問題での注意

次に来る入力がランダムな問題では、同じ手順でも結果が毎回変わります。ノードに状態を保存して使い回すことはできません。木をたどるたびに、乱数で状態を計算し直します。

## よくある失敗

候補が多い問題に最初からMCTSを使うと、木が広がりすぎて深い手まで展開できません。terry_u16さんはAHC040で、中盤までをビームサーチで進め、最後の約15手だけをMCTSで探索しています。
