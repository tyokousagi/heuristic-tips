# 評価関数の設計

探索に使う評価関数は、問題のスコアと同じである必要はありません。探索がよい解へ進みやすい形に作り変えます。

## 問題のスコアをそのまま使えない場合

次のような問題では、スコアをそのまま使うと探索が進みません。

- スコアが最小値や最大値で決まる。ほかの値を改善しても、スコアが変わりません
- スコアが段階的にしか変わらない。同じスコアの解が広く続きます
- 条件を満たすまでスコアが0のまま。条件に近づいているかどうかがわかりません

## 作り変え方

最小値を最大化する問題では、最小値に加えて、2番目に小さい値や全体の合計を小さな重みで足します。最小値以外の改善が評価に現れます。

段階的なスコアは切り捨ての前の連続値に戻します。問題文の式に四捨五入や切り捨てがあれば、それを外した値で評価します。

条件を満たすまで0点の問題では条件までの近さを表す値を作ります。違反の数、目標までの距離、残りの手数などです。

作り変えた評価関数で最もよい解が、問題のスコアでも最もよい解に近いことを確かめます。評価の値そのものが一致する必要はありません。

## 途中の状態の評価

ビームサーチのように解を組み立てる途中で比べる場合は、確定したスコアに、残りの見込みを足します。くわしくは[ビームサーチの評価と多様性](/methods/beam-eval)に書いています。

## 項の足し方

評価関数には観察した問題点に対応する項を1つずつ足していきます。

1. 単純な評価で動かします。
2. ビジュアライザで、困っている状況を見つけます。
3. その状況を悪く評価する項を足します。
4. 多数のケースで比べて、上がれば残します。

項の重みは、最初は手で決めます。項が増えたら、重みをパラメータにして自動で調整します。

短期コンテストでは重みの調整に時間を使えません。制約として扱えるものは評価に入れず、遷移の条件にします。

## 速さとの兼ね合い

正確な評価は時間がかかります。少し粗くても速い評価のほうが、試行回数が増えて結果がよくなることがあります。

評価の精度を段階的に上げる方法もあります。序盤は粗い評価で大まかな形を作り、終盤に正確な評価へ切り替えます。
