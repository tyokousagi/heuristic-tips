# 最短路と前計算

移動を含む問題では2点間の距離を何度も使う。探索を始める前に距離を計算して表にしておくと、探索の中では表を引くだけで済む。

## 手法の使い分け

| 状況 | 手法 |
|---|---|
| 辺の重みがすべて同じ | BFS |
| 辺の重みが0か1 | 0-1 BFS |
| 辺の重みが正で、ばらばら | ダイクストラ法 |
| 頂点が数百までで、全点間の距離が要る | ワーシャル・フロイド法 |

## 全点間の距離

頂点の数がNのとき、各頂点からBFSかダイクストラ法を行えば、全点間の距離が求まる。グリッドでマスの数が1000なら、表の大きさは100万だ。

表は1次元の配列で持ち、`dist[a * N + b]` の形で引く。値が小さければ16ビットの型にして、メモリを減らす。

経路の復元が必要なら、距離の表に加えて、「aからbへ行くとき最初に進む方向」の表を作る。この表をたどれば、経路を1歩ずつ取り出せる。

## 重要な点だけの距離

荷物や目的地などの重要な点のあいだの距離だけが要る問題がある。その場合は、重要な点からだけ探索を行い、重要な点どうしの距離の表を作る。問題は小さな完全グラフの上の問題になる。

## 盤面が変わる場合

探索の途中で障害物が増えるなど、盤面が変わる問題では、前計算した距離がそのまま使えない。次の方法がある。

- 変わった部分の影響が小さいなら、前計算の値を近似として使う
- 変わるたびに、関係する範囲だけを計算し直す
- マンハッタン距離など、盤面によらない下界を評価に使う

## 推定した重みでの最短路

辺の重みがわからず、推定しながら経路を選ぶ問題では、推定した重みでダイクストラ法を実行する。推定が不確かな辺の重みを少し小さくすると、情報の少ない辺が選ばれやすくなり、推定が進む。
