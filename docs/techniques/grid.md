# グリッドの扱い

AHCでは2次元のグリッドを扱う問題が多く出ます。方向の表し方、座標の持ち方、探索の書き方を決めておくと、実装が速くなります。

## 方向

4方向を上、右、下、左の順に番号で持ちます。この順なら、番号に2を足して4で割った余りが逆向きになり、1を足すと右回りに90度回ります。

出力に使う文字も同じ順の配列にしておきます。問題によって文字が違うので、問題文を見て書き換えます。

## 番兵と1次元の添字

グリッドの外周に壁を1マス足し、全体を1次元の配列で持ちます。隣のマスは添字に決まった値を足すだけで求まります。外周が壁なので、範囲の外へ出る心配がなく、判定を省けます。

## BFS

障害物のあるグリッドでの最短距離は、BFSで求めます。上のスニペットの `bfs` は、キューを配列で持ち、先頭の位置を進めていく形です。`std::queue` より速く動きます。

BFSを何度も繰り返す場合は、距離の配列を毎回作り直さないようにします。配列を外で確保し、[一括クリアが速い配列](/snippets/#stamp-set)で訪問済みを管理します。

## 前計算

盤面が変わらないなら、すべてのマスの組の距離を前計算できます。マスの数がNなら、BFSをN回行って、N×Nの表を作ります。Nが数千までなら間に合います。

隣のマスの一覧も、前計算しておくと探索が速くなります。

## 連結性

「マスを1つ消しても、残りがつながっているか」という判定は、全体を探索すると時間がかかります。周りの3×3マスだけを見て判定する方法があります。厳密ではありませんが、連結を保つ側に誤るので、連結性は保たれます。

連結成分の管理には[Union-Find](/snippets/#dsu)を使います。Union-Findは辺の削除ができないので、削除がある場合は作り直すか、別の方法を使います。

## 小さい盤面

盤面が小さく、大きさが決まっている場合は、マスの集合を整数のビットで表せます。移動はビットシフト、重なりの判定はANDになります。左右のシフトで端のマスが隣の行へ回り込むので、ダミーの列を足して防ぎます。

## 複数の物が動く場合

複数の物が同時に動く問題では、時間を3つ目の軸にした空間で経路を探します。「時刻tにマスvにいる」を1つの頂点とみなします。待つことは、同じマスで時刻だけが進む辺になります。
