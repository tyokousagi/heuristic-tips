# 高速化全般

プログラムを速くすると、同じ時間でより多くの解を調べられます。効果の大きい順に取り組みます。

## 取り組む順番

1. 計算量を下げます。差分計算にする、前計算する、変わった部分だけを更新する、などです。
2. 無駄な処理を除きます。ループの中のメモリ確保、不要なコピー、毎回の時刻の取得などです。
3. データの持ち方を変えます。小さい型にする、1次元の配列にする、などです。
4. 定数倍を詰めます。分岐を減らす、SIMDを使う、などです。

上の項目ほど効果が大きく、実装も壊れにくい傾向があります。4番目は時間がかかる割に効果が小さいことが多いので、長期コンテストの終盤に回します。

## 計測

高速化の前に、制限時間を延ばすとスコアが上がるかを確かめます。上がらないなら、高速化してもスコアは変わりません。

遅い場所はプロファイラで探します。手軽な方法として、反復回数を出力し、変更の前後で比べるやり方もあります。

速くなったかどうかは実測で判断します。理屈では速くなるはずの変更が、かえって遅くなることがあります。

## メモリ

- 配列はループの外で確保し、使い回します
- 大きさが決まっているなら、固定長の配列を使います
- 2次元の座標は1つの整数にまとめます
- 大きな配列には、値が収まる最小の型を使います
- 何度も初期化する配列は、[一括クリアが速い配列](/snippets/#stamp-set)に置き換えます

状態をコピーする探索では、状態の大きさがそのまま速度に影響します。

## 計算の省略

- 距離や累乗など、繰り返し使う値は表にします
- 剰余を比較と引き算や、掛け算とシフトに置き換えます
- グリッドの外周に番兵を置き、範囲外の判定を省きます
- スコアの計算の途中で結果が決まったら、残りを打ち切ります

## コンパイラ

ソースの先頭に最適化の指定を書けます。

```cpp
#pragma GCC optimize("O3,unroll-loops")
```

速くなるかどうかはプログラムによります。指定の有無で反復回数を比べます。

手元のコンパイラとジャッジのコンパイラが違うと、結果も違います。細かい高速化はジャッジに近い環境で確かめます。

## やめどきの判断

5%に満たない高速化を追うより、パラメータの調整や近傍の改善のほうが、少ない手間でスコアが上がることが多いです。コードが複雑になる高速化は、バグの原因にもなります。
