# 時間計測

制限時間いっぱいまで探索するために、経過時間を測ります。時刻の取得は軽い処理ではないので、呼ぶ回数を抑えます。

## 呼ぶ回数

1回の試行が数十ナノ秒で終わる焼きなましでは、毎回の時刻の取得が全体の速度を落とします。数百回に1回だけ取得します。

```cpp
if ((iterations & 255) == 0) {
    if (timer.elapsed() > TIME_LIMIT) break;
}
```

間隔は1回の試行の重さに合わせます。1回の試行が重い探索で間隔を広げすぎると、制限時間を超えます。次の時刻の確認までにかかる時間が、数ミリ秒に収まるようにします。

## 終了時刻の決め方

探索を終える時刻は制限時間より少し手前にします。入力の読み込み、出力、プログラムの起動と終了にかかる時間を残すためです。2秒の制限なら、1.9秒から1.95秒ほどにします。

手元の計算機とジャッジの計算機では、速さが違います。終了時刻を攻めすぎると、ジャッジで時間超過になります。提出して実行時間を確かめます。

## 複数の段階がある場合

初期解の構築、主な探索、仕上げのように段階が分かれる場合は、段階ごとの終了時刻を全体の制限からの割合で決めます。前の段階が予定より長くかかっても、あとの段階が残り時間に合わせて動くようにします。

ターンごとに探索する問題では、残り時間を残りのターン数で割った値を、そのターンの持ち時間にします。

## 手元での並列実行

テストを並列に実行すると、1ケースあたりの実行が遅くなることがあります。反復回数が減り、スコアも少し下がります。時間ぎりぎりの解法を比べるときは、並列の数を物理コアの数より少なくします。
